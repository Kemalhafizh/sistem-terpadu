## FASE 95: PROFIL DIGITAL SISWA 360° API `[RENCANA]`

Fungsi inti API "Big Data Siswa" SISTA App yang mengagregasikan informasi rekam jejak dari minimal 7+ sumber tabel berbeda ke dalam satu JSON view utuh. Disebut profil 360 derajat mencakup akademik, karakter keislaman, kesehatan, hingga ekstrakurikuler.

### 95.1: NEW Controller - StudentProfileApiController
Mengelola 8 endpoints agregasi:
- `GET /comprehensive` (Profil penuh siswa login)
- `GET /academic-summary` (Indikator kurikuler khusus)
- `GET /ibadah-summary` (Indikator Diniyyah / Mutabaah)
- `GET /achievement-summary` (List prestasi/piagam)

- `GET /parent/child/{id}/profile` (Versi untuk orang tua)
- `GET /teacher/student/{id}/profile` (Versi analitik wali kelas)

### 95.2: NEW Service - StudentProfile360Service
- `getComprehensiveProfile(int $studentId)`: Heavy Query yang menggunakan kombinasi Eager Loading ke relasi `grades`, `tahfidz`, `mutabaah_yaumiyah`, `extracurriculars`, `achievements`, `discipline_points`, dan `uks_visits`.

## FASE 97: JURNAL MENGAJAR GURU MOBILE API `[RENCANA]`

Digitalisasi Jurnal KBM harian (Kurikulum Merdeka). Sistem log kewajiban guru setelah mengajar yang ringkas diakses langsung seusai sesi di kelas dari HP tanpa harus membuka laptop.
*(Catatan: Menggunakan base table `teaching_journals` dengan optimasi).*

### 97.1: NEW Controller - TeachingJournalMobileApiController
Mengelola 5 endpoints API:
- `GET /journals` (Daftar jurnal pribadi bulanan/mingguan)
- `POST /journals` (Form entri baru selesai mengajar)
- `PUT /journals/{id}` (Update revisi catatan jam KBM)
- `GET /journals/summary` (Cek tingkat kepatuhan guru harian)
- `GET /admin/journals/report` (Rekap kepala sekolah/waka kurikulum untuk melihat semua guru)

### 97.2: NEW Service - TeachingJournalMobileService
- `createJournal(array $data)`: Wajib disambungkan pada `schedule_id` dan mencatat `materi_pokok`, `metode_pembelajaran` (Enum: Ceramah/Diskusi/Praktikum/PBL/PJBL/Jigsaw), `media_pembelajaran`, kehadiran kelas (`jumlah_hadir`, `tidak_hadir`), `kompetensi_tercapai` (boolean flag), `kendala`, dan `tindak_lanjut`.
- `getMonthlyCompletion(int $teacherId)`: Metrik Kepatuhan - menghitung perbandingan target `total_jadwal` KBM dengan `total_jurnal_terisi` untuk mendapatkan `persentase_kepatuhan` (%).
- `getAdminReport()`: Array ringkasan perbandingan semua staf guru (compliance audit).
- `notifyMissingJournal()`: Scheduler daily run jam 15:00 WIB untuk broadcast notif push ke guru yang belum isi jurnal padahal ia ada KBM di hari tersebut.
- `Constraint`: Maksimum 1 Jurnal per 1 instance jadwal harian (cegah double post).

### 97.3: Test Plan
1. ✅ Tes parameter validasi menolak input jurnal jika `schedule_id` yang direferensikan bukan hari ini atau tidak valid.
2. ✅ Tes logic _Duplicate Prevention_ - `POST` kedua untuk jadwal yang sama merespons `409 Conflict`.
3. ✅ Tes logic persentase kepatuhan pada endpoint `/summary` (Misal: dari 5 kelas hari ini baru lapor 2, maka persentase 40%).
4. ✅ Tes _Scheduled Task_ peringatan berjalan pada pukul 15:00 bagi array pengguna tanpa record aktivitas `teaching_journals`.
5. ✅ Tes view admin menampilkan ranking guru yang paling rajin mengisi jurnal harian.
